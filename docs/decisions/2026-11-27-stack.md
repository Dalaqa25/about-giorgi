# Stack: static Next.js, TypeScript, one file per section

Date: 2026-11-27
Status: accepted

## Context

The site is a single About Me page. It needs to load fast, cost nothing to host and stay easy to change. Several tickets will work on it at the same time.

## Decision

1. Use Next.js App Router with static export, written in TypeScript, styled with plain CSS.
2. Start from no template and use no UI library.
3. Put each section in its own file in `src/sections/`. `src/app/page.tsx` only composes them.

## Why

**Static Next.js with TypeScript.** The page has no server logic, so a static export gives plain files that any static host can serve. App Router keeps the structure standard if the site grows. TypeScript catches broken props and imports at build time, before they reach the page.

**No template.** A template brings its own look, its own dependencies and code nobody here wrote. The design is a specific "engineer's notebook" style with a fixed palette, and fighting a template to reach it costs more than starting clean. Plain CSS keeps every style visible and removes a dependency to maintain. The same goes for UI libraries.

**One file per section.** Parallel tickets each own one section: Hero, Shipped, HowBuilt, Life or Contact. Two tickets then rarely touch the same file, so merges stay clean. `page.tsx` holds no content, so it stays stable.

## Consequences

- No server features such as API routes or server-side rendering. Anything needing them means a new decision record.
- Shared styles need care, because sections must not depend on each other's CSS.
- `npm run build` must keep producing a static export.
